# Private AX runtime bridge

Build this command inside the pinned AX source tree so its typed AX, Substrate and guest API dependencies match the deployed pair. `scripts/ecs_ax/test-bridge.sh` creates fresh temporary checkouts, applies the reviewed compatibility patch and runs their complete Go suite plus the bridge tests. Copy this directory's Go files to `cmd/raptor-bridge` in that tree and build with `CGO_ENABLED=0`; the Dockerfile consumes `bin/linux_amd64/raptor-bridge`.

The bridge exposes POST `/v1/runtime` on private ECS port8443 with TLS1.3 and a verified client certificate named `raptor-gateway`. Its Kubernetes manifest is `infra-kubernetes/environments/rdev.ali/ecs-ax/bridge.json`. Provide a private TLS Secret `raptor-ax-bridge-tls` containing `tls.crt`, `tls.key`, and `ca.crt`; no key belongs in Git. The gateway client uses a separate client key, copied into its private memory volume by Helm. POC leaf certificates expire after90days; renew the Secret and restart both deployments before expiry.

Only attempt-bound `application.question` operations in rdev.ali are accepted. New attempts use the fixed image; each persisted nonsecret attempt marker records its binding and image so later upgrades do not change ownership. Creation and process-start markers are fsynced before remote mutations. Ambiguous outcomes are never retried as new inference. Recovery only observes existing processes/results and deletes exact owned tasks; deletion must prove both AX task and Substrate actor absence.

AX Tasks have no declarative command. DATA resume restores `/workspace/raptor-state` while private MCP access and job files remain under `/tmp/raptor-private`, outside snapshots. Portable Pi checkpoint archives are staged under `/tmp/raptor-oss`; the gateway validates their SHA/size, publishes with OSS AES256 encryption, and verifies remote readback. Opaque Substrate snapshots are not portable checkpoints. The guest file service is workspace-confined, so private staging uses a fixed validated shell path with bytes sent through process stdin. Model execution commands are fixed and separately journaled.

No bridge receives cloud controller credentials. The AX control Service admits only bridge pods; keep all AX/Redis/registry endpoints private. A single ECS persists across workload restarts but provides no high availability or protection against loss of its disk. Cleanup verifies actor/task disappearance and revokes request access; upstream snapshot object garbage collection is a separate storage lifecycle concern.
