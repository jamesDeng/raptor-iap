# Private rdev platform deployment

Prepared packaging and bootstrap, not a cloud deployment receipt. Run only after main image publishing, the reviewed Argo RBAC approval, fresh owned-resource verification and private RDS TLS readiness.

The five Services remain ClusterIP. Argo CD and browser/admin access are private. Gateway simulation is false and its real worker is not implemented; an accepted queued request is not agent execution. The previous Infra API probe was removed; deployment discovery remains unavailable until a real Infra API is redeployed and wired to this environment.

## Release and private bootstrap
Publish main images through Platform images. Packaging checks, release contracts and real PostgreSQL14 acceptance must pass before publication. Record both SHA256 image digests. The release chart refuses unresolved digests, source commit and application codes. Generated codes come from the one-shot catalog seed and remain stable on a safe retry; they are not invented from component names.

Prepare a private JSON config with the exact owned account, region, cluster and RDS IDs, private RDS host, reviewed source_sha, raptor_image/gateway_image digest references and the official PostgreSQL14 image digest. `scripts/rdev/platform_bootstrap.py --config PRIVATE_CONFIG` previews without mutation. `--prepare-directory .raptor-local/platform-kit --confirm rdev.ali` generates a mode700 directory containing mode600 credentials/manifests. Do not commit, paste, print or attach the kit to a PR. No cloud call occurs during kit generation.

RDS TLS was off at inspection. The Terraform change sets ssl_action=Open. Validate a fresh saved plan with platform_bootstrap.validate_tls_plan: exactly one in-place owned RDS TLS update, all other actions no-op. Read the live caller/owned tags again immediately before a reviewed operator apply. Existing protected creation workflow and its deployment role are unchanged and must not be used for an update. Verify SSLEnabled=on afterward. A read-only certificate verification and server-name trust setup should precede production use; this POC currently requires encrypted transport via sslmode=require rather than asserting full server certificate validation.

After approval of the named bootstrap account, `--account-kit PRIVATE_KIT --execute --confirm rdev.ali` verifies live account/RDS/cluster/VPC/tags/private endpoint and TLS, then submits only CreateAccount for raptor_bootstrap. It records intent before the call and refuses automatic replay or credential reset after ambiguity. Any existing account or intent needs reconciliation. Wait for AccountStatus=Available independently. The privileged bootstrap account is used only for initial database/role creation, never mounted in service Deployments; retained account credentials remain private for operator reconciliation. Future removal needs ownership/dependency reconciliation first.

Upload the private kit only to the authenticated rdev Workbench session, restore mode700/600 immediately, and never echo Secret content. Execute the reviewed public bootstrap script from the exact Git revision. `platform-bootstrap.sh verify` reads endpoint/node/workloads only. For mutations the third argument must be `rdev.ali`; use stages database, migrations, catalog, cleanup-bootstrap, and argocd. These are one-shot creation stages, not blind retry commands: inspect partial success before any repeat. Bootstrap Secret cleanup requires all jobs complete; missing evidence blocks deletion. If Job TTL expiry removed success evidence, reconcile the database and migration state before credential cleanup. No database or namespace is dropped.

The SQL initializes one database, NOLOGIN schema owners, a NOINHERIT migrator and separate runtime users. Both migration binaries use SET LOCAL ROLE for their own schema. Runtime DSNs cap each pool at10. Catalog seeding holds an advisory transaction lock, rejects conflicting environment/catalog ownership, uses the same UUID format as Raptor, creates five application objects, and prints only their non-secret code mapping.

The Argo stage installs only checksum-pinned upstream Argo CDv3.5.3 into the owned argocd namespace and waits for core controllers; its upstream ClusterRoles/Bindings require explicit review before execution. It does not expose a public endpoint. Populate real release values in infra-kubernetes/environments/rdev.ali/values.yaml and review/merge them. Apply the rdev-platform AppProject and Application from that revision. The Project permits only Deployments/Services in raptor-system from this monorepo; auto pruning is disabled initially.

Keep this Pod transient, delete only that Pod after creation, and do not put the password in a manifest or shell command. Argo initial admin credentials must similarly remain private; do not print them in chat.

Verify all Argo controllers and the rdev-platform Application are Healthy/Synced at the actual Git revision, then all five Deployment rollouts.
