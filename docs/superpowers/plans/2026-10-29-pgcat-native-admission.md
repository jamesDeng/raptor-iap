# Native PgCat Admission and Evidence Ingress Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development for parent execution/review coordination. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers never spawn extra agents or reviewers.

**Goal:** Build source-bound native observer startup and worker-authenticated evidence ingestion, including a real disabled-proof application restart, while keeping live admission closed until closure unit C is complete.

**Architecture:** Add one worker authority helper and one narrow native controller, reusing the existing Journal, fixed ActionCatalog, owned Popen/start barrier and detached collector guardian. Capture starts with an immutable plan and baseline; actual Raptor identity is appended afterward through existing authenticated reads. Unit B supplies evidence consistency; A establishes origin and startup/action authority; C supplies final assessment and closure.

**Tech Stack:** Python3.6-compatible standard library worker code, existing Mac Python lane/SQLite Journal, Workbench CLI, Kubernetes API and existing Raptor/Gateway HTTP APIs; unittest with offline transports. No new dependency.

**Spec:** [Native observer design](../specs/2026-10-29-pgcat-native-observer-design.md). Read the committed [rolling evidence B plan](2026-10-29-pgcat-native-rolling-evidence.md) first; reconcile its reviewed implementation interfaces before editing shared collector files.

## Global Constraints

- Observer/provider/collector mode is `full-replacement-direct-v2`; harness profile is `direct-v2`, native result version2. Immutable `executionKind` is exactly `native-replacement` or `disabled-proof`, never inferred from missing fields or changed on resume.
- All fleet mutations and approvals belong to Raptor/Infra. Native ActionCatalog must reject every local ESS scale, NLB registration/deregistration and protection operation, including historical staged templates. Diagnostic restart is the only application restart support action and is forbidden for native-replacement.
- Keep `_release_admission` denying the new mode, including disabled-proof, throughout A. No environment override, test flag, alternate CLI entry or direct-helper bypass may admit a live action. Unit tests exercise pure validators and injected offline adapters; future C supplies the reviewed activation change.
- Preserve v1 records, exact legacy source closure and staged/disabled-rehearsal guards. Lazy imports and a separate exact native closure cover every transitive local module. Do not move skills-v0.4.0 or rewrite stored results.
- Plan/baseline and two committed ready frames precede normal signed-in Raptor request creation. Raptor Create immediately queues dispatch; no draft/withhold API exists. Binding afterward records evidence, not authorization, and never rewrites context.
- No new service, resource, HTTP route, DB reader/provenance store, arbitrary shell, credentials on Mac/argv/logs, or extra paid rehearsal. Existing local Journal remains the durable admission owner.
- Full run requires transition and authenticated native binding. Diagnostic qualification requires exact constant original-two fleet and Gateway replacement=false throughout; only C may call its separately labelled ordinary assessment with `require_transition=False`. No diagnostic-to-native PASS upgrade. Preserve FAIL > INCONCLUSIVE > PASS and all cohort histories.
- Future live preflight: CNY1,800 whole-POC net ceiling, once-per-day billing check, no paid mutation after21:30 Asia/Shanghai, stop/closure by22:30, Workbench CLI priority, and reserve120s final hold plus assessment/restoration/cleanup. The ceiling never resets daily.

## Review Focus

- Capture readiness forged, late or stale: request creation/diagnostic restart remains unavailable (`test_native_ready_requires_committed_frames_and_live_processes`).
- Wrong execution kind or request/scope/model/skills: fail before sealing binding; diagnostic never receives native identity (`test_native_ingress_kind_and_identity_are_bound`).
- Secret reference ambiguity, redirect or leaking error body: refuse without persisting/outputting credentials (`test_ingress_fixed_origins_and_secret_resolution`).
- Missing/duplicated event pages or changed attempt: retain all evidence and refuse a complete chronology claim (`test_ingress_complete_attempt_spanning_event_pages`).
- Parent/guardian death, PID reuse or swapped credential inode: retain incomplete state; never infer ownership or cleanup (`test_native_owned_processes_and_credential_identity`).

## Verified source facts and limits

- `modelproviders/http.go` browser GET `/api/v1/model-providers` returns enabled `{providerId,modelId,displayName,default}` rows (`PolicyStore.ListEnabled`); it does **not** return connectionVersion. The admin list does expose connectionVersion, but this plan neither requires admin access nor treats a pre-create read as the eventual bound version. `requests/service.go:Create` rejects a nonzero incoming connectionVersion and obtains it internally through ValidateSelection. Bind it only from authenticated post-create context/input.
- `components/raptor/internal/requests/service.go` creates request and dispatch outbox together. Existing browser POST `/api/v1/requests` remains the creation path; the observer neither creates a service-auth request nor uses post-create blocking as a startup barrier.
- `components/raptor/internal/openapi/server.go` Basic-authenticates and proxies `/v1/` to the backend. `backend/service.go` supports GET `/v1/requests/{id}/context` with `{data:{requestId,definition,environment,skills,definitionSha256}}`; GET `/control` with requestId/status/controlState; GET `/deployments?env=...`; and GET `/approvals/{approvalId}`. Approval data is `{approvalId,requestId,actionId,binding,state,guidance}`. There is no approval-list or submission-record GET here.
- Gateway `httpapi/server.go` Basic-authenticates GET `/v1/requests/{id}` and `/events?after=N`. Request response is `{data:Execution}`; relevant Execution fields are requestId/attemptId/input/appliedSkills/result/status/runtimeMode/stage/cleanup/recoveryNeeded. Input contains definitionSha256/definition/environment/skills. Result contains selectedModel/actualModel, requestId/attemptId and replacement. Use source schemas, not public Raptor answer text.
- Events response is `{data:[ProgressEvent],nextAfter,hasMore}`, at most100 events. Each event has requestId/attemptId/sequence/occurredAt/kind/details/evidenceMode. Runtime details carry tool/status/runtimeSequence, not tool arguments. Guest tool-start occurredAt precedes the call; `execution/live_journal.go` preserves it. RuntimeSequence is attempt-local, sequence is request-wide; do not demand that every request event has runtime details.
- `execution/replacement_result.go` v2 contains scope, exact old/new pairs, restartGeneration and two ordered actions2→4/4→2. Outcomes may be `submitted` **or `unknown`**. Scope is available in this authenticated result; context GET does not return the issued attempt's replacement scope. No new introspection credential, checkpoint parser or database read is needed. Compare result scope with the bound plan and source-pinned controller scope; do not claim a GET proved the issued credential scope.
- Helm `helm-chart/raptor-platform/templates/services.yaml` supplies Gateway service credentials through **envFrom.secretRef `gateway-runtime`**, not explicit SERVICE_* secretKeyRefs; OpenAPI uses `platform-service-auth`. Services expose8874/8872. Gateway live RAPTOR_OPEN_API_URL may be an HTTPS serviceURL; do not blindly reuse that value as a worker-approved URL. Resolve the exact bound Deployment's effective credential references, including explicit SecretKeyRef precedence if present; reject duplicate/conflicting definitions. Read only SERVICE_USERNAME/PASSWORD into worker memory.
- Gateway flag source is JSON: `tools/gateway-live-gate/main.go:secretConfig` decodes Secret data["config.json"] as base64 JSON, and `runtime.LiveConfig` reads JSON. The Go tool has only set/rollout/verify, **no standalone read/check**. Existing `verify --expected false --resource-version <actualRV> --changed-after <actualTransitionTime>` returns exact `{replacementEnabled,generation,ready,podUID}` after checking the ready bound Gateway runtime, Secret equality and effective copied config bytes (`runtime_binding.go`). Do not invent a transition timestamp to call it. A1 reads the fixed Secret through kube_read and records the configuration flag only; production admission additionally needs A2/C's current bound runtime-disabled verification. Secret=false alone cannot establish the flag loaded by an older Gateway Pod.
- Approval ID is absent from the replacement result. An operator-provided approval ID may be an untrusted lookup selector; authenticated GET must prove its exact request/action/interface/target/parameters and approved state. It does not prove provider submission. C must evaluate unknown outcomes against actual ordered tool events, exact approved binding and independent provider reconciliation, never relabel unknown as submitted. Missing required evidence means INCONCLUSIVE, not a new endpoint or fabricated record.
