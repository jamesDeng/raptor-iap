# Native PgCat Rolling Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development for parent execution/review coordination. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers never spawn extra agents or reviewers.

**Goal:** Represent one bound rolling restart in authenticated retained client evidence and derive an exact successor-pair finalization boundary without enabling native runtime actions.

**Architecture:** Add a small native evidence module and explicit v2 branches in the existing collector/progress code. Reuse actual committed SourceFrameRef records and ordinary whole-window assessment. Preserve v1 original-roster paths; future units supply authenticated native request/result ingress and integrate process/closure authority.

**Tech Stack:** Python3.6-compatible standard library worker code, current Mac Python lane, unittest, existing private JSON/fsync/source-frame helpers. No new dependency.

**Spec:** [Native PgCat observer design](../specs/2026-10-29-pgcat-native-observer-design.md).

## Global Constraints

- Python observer mode is `full-replacement-direct-v2`; native result is version2 and harness profile is `direct-v2`. Immutable plan/context executionKind is exactly `native-replacement` or `disabled-proof`; operation-binding kind must match and cannot upgrade on resume.
- Preserve legacy v1 originalRoster behavior and staged/disabled-rehearsal captures. Do not move skills-v0.4.0.
- Exactly two initial plus two successor process identities, one Deployment UID, one immutable client image digest, one generation increment and one new ReplicaSet/template hash.
- Immutable planSha256 precedes Raptor creation; native request/result binding is appended later. Disabled proof instead appends its real operator restart receipt binding, with no fabricated request/model/result. Neither rewrites baseline or grants authorization.
- Retain all predecessor/successor history and settled finals. Whole ordinary assessment retains FAIL > INCONCLUSIVE > PASS. Future C may set require_transition=False only for disabled-proof plus exact constant-two-fleet/Gateway-false evidence; full acceptance always requires transition and native binding. B adds no verdict or runtime admission switch.
- Reuse exact SourceFrameRef shape, private-file/source identity checks, one-second capture clock, gap≤3s and five-second final settling limit.
- No controller/profile admission, source release switch, API/credential reader, cloud action, Go change, provider change, new service/resource/DB or shell bypass in unit B. Existing runtime remains disabled.
- Future A/C own all source-registry/runtime/guardian/authority/verdict/cleanup integration. Existing guardian and CLI must remain unable to construct native v2 context after B alone. Native imports must be lazy and confined to v2 paths, so legacy verified v1 source closures do not acquire an unpinned transitive import.
- Full POC preflight later applies the CNY1,800 whole-POC net ceiling (never a daily reset), once-per-day billing checks,21:30 mutation cutoff and22:30 stop/closure, Workbench priority and120s hold headroom.
- Exact client Deployment is `raptor-test/rdev-test-client-client`; initial generation is a positive safe integer with room for one increment. A normal rollout may have status.observedGeneration lag metadata.generation; this alone is not a regression or identity failure.

## Review Focus

- Late authenticated binding must validate already-captured successor history without rewriting/resetting it (`test_late_binding_preserves_early_successor_history`).
- A matching label with foreign ReplicaSet/Deployment UID or image must never become a successor (`test_native_owner_chain_and_image_required`).
- Reused Pod/container/process identity and a second rollout cannot fit the four-member cohort (`test_native_rejects_reincarnation_extra_cohort_and_generation`).
- A forged or replaced frame/reference/current roster cannot select the final pair (`test_terminal_witness_reads_committed_refs_and_live_owners`).
- A real earlier SQL failure survives malformed new evidence or uncertain finalization (`test_native_failure_survives_late_binding_and_finish_error`).

**Interfaces and exact records:**

1. `pgcat_native_evidence.validate_context(value: dict) -> dict` returns a detached canonical copy. Exact v2 keys:
   `schemaVersion,mode,executionKind,runId,feedSession,providerRunContextSha256,bundleSha256,sourceHashes,baselineSha256,planSha256,initialRoster,deployment,collectorIdentity`.
   Values: schemaVersion2; fixed mode; executionKind exactly native-replacement or disabled-proof and included in the immutable plan hash; UUID run/feed; lowercase64-hex hashes; existing collector identity; sourceHashes is legacy collector source set plus `nativeEvidence`; initialRoster uses existing exact four-key `{name,uid,containerId,processId}` roster shape, sorted by uid, exactly2. Deployment exact keys `{name,namespace,uid,generation,initialReplicaSetUid,initialTemplateHash,imageDigest}` with fixed POC name/namespace, generation positive int and imageDigest `sha256:`+64hex. Context is immutable.
2. `worker_capture.native_owner_evidence(deployment: dict, replicasets: list, pods: list, context: dict) -> dict` validates authoritative raw Kubernetes inputs and returns a mapping by Pod UID to exact `{deploymentUid,replicaSetUid,templateHash,imageDigest,terminating}`. Require one controller owner at each edge, exact named Deployment UID, exact one client container and runtime image digest, matching RS/Pod template-hash and bound image; initial RS/hash match context, successors use one distinct pair. No labels-only trust. Existing Kubernetes reader obtains the RS list in namespace using the bound deployment selector; join by UID and fail closed on ambiguity. Native `capture_frame(..., native_context=None)` adds these sanitized records under each pod's `ownership`; default behavior stays identical. Raw objects never persist.
3. `NativeCohort(context: dict)` in the new module exposes `observe(frame: dict) -> None`, `committed(frame: dict, ref: dict) -> None`, `snapshot() -> dict`. It owns bounded4 identities, immutable owner/image/template fields, first/final refs and observed generation transition. `terminating` is an observed lifecycle boolean, not an immutable identity field; a normal false→true transition must not trigger an owner mismatch. `observe` records sticky flags, never erases earlier adverse evidence; `committed` only receives frame bytes reread after fsync by existing `_committed`. A final must have connected0, Scheduled=Attempts+Skipped and immutable subsequent counters; missing/skipped evidence remains adverse. Disappearance requires a previously committed final reference, not merely an uncommitted observed final. Validate full successor event history from sequence1 (ordinary assessor remains authoritative for complete accounting). Return snapshot with exact `{schemaVersion,cohort,successorReplicaSetUid,successorTemplateHash,observedGeneration,flags}`; cohort rows exact `{identity,ownership,firstFrame,finalFrame}`, refs nullable until committed; flags reuse existing FLAGS. Snapshot observedGeneration means the highest validated metadata.generation seen in committed frames, distinct from the frame's Kubernetes status.observedGeneration. Initial+1 may be provisionally observed before actual binding; regression/other generation refuses acceptance.
4. `segmented_capture.validate_context/read_progress` select v1 or native v2 strictly. Native progress preserves current progress keys with schemaVersion2 and adds `nativeCohort` from the bounded snapshot. `progress-binding.json` retains immutable context plus existing directory identity. Native flags apply all observed cohorts, permit expected rollout readiness/termination, and reject foreign/extra identity; v1 remains byte/shape compatible. `final_refs` retains all four processes, not only the initial pair. Do not add mutable request data to progress-binding.
5. `validate_operation_binding(value: dict, context: dict) -> dict` consumes one of two disjoint exact schemas. Native keys: `{schemaVersion,kind,planSha256,requestId,definitionSha256,skillsCommit,model,restartGeneration,resultSha256,eventsSha256,ingressSha256}` with kind=native-replacement. Disabled keys: `{schemaVersion,kind,planSha256,restartGeneration,restartReceiptSha256,ingressSha256}` with kind=disabled-proof. Both require schemaVersion1, matching context executionKind/planSha256, lowercase64hex hashes and restartGeneration exactly initial+1. Native additionally requires request UUID, skillsCommit40hex and bounded nonempty model; disabled rejects all native-only fields. Return detached canonical copy. This validates internal consistency, NOT origin/authentication. Future A authenticates native Gateway v2 result/events or the fixed UID-bound operator restart receipt and Gateway-false/constant-two-fleet proof respectively. No fake native result is needed or accepted for diagnostic finish.
6. `seal_terminal_clients(capture_dir: Path, context: dict, operation_binding: dict, live_read: callable, *, now: callable) -> dict` rereads `read_progress` and actual prior/latest committed frames, revalidates directory/ref/hash/sequence and calls `live_read() -> {deployment,replicaSets,pods,roster}` where roster is independent `finish_clients.live_roster`. Both committed frames have identical exact two ready nonterminating successors, no initial pod, generation=observedGeneration=bound restartGeneration, desired2/ready2, each frame age≤3s and gap≤3s. Live owner/status/roster agrees. Both predecessor final refs exist, are reread and precede disappearance; all four first refs and successors' startup histories retained. Seal O_EXCL `terminal-clients.json` with exact `{schemaVersion,mode,executionKind,runId,planSha256,progressBindingSha256,operationBindingSha256,generation,roster,frames,predecessorFinals,cohort}` where frames is exact `{previous,latest}`, predecessorFinals two `{uid,processId,frame}` rows and cohort the four committed snapshot rows. Return `{terminalSha256,roster}`. Refuse duplicate seal, changed binding, stale/live mismatch or sticky invalid evidence. Authenticated SQL failure must still remain available to ordinary assessment even if sealing refuses.
7. `read_terminal_clients(capture_dir: Path, context: dict, operation_binding: dict) -> dict` verifies exact sealed bytes and referenced committed frames and returns same digest/roster. This is a historical sealed-proof getter: do not require now-fresh frames or the sealed historical latest ref to remain the current growing file tail, including after the120s hold. Freshness/current-roster checks occur at sealing and future action-time admission; immutable frame bytes/binding checks remain on reads. Future C calls `finish_clients.finish(boundary_dir, expected_roster=result['roster'], deadline=..., kubeconfig=...)` only after its stop/authority checks. B does not dispatch finish or verify stopped provider.
8. `worker_capture.run_capture` native branch, on boundary request, requires `terminal-clients.json` match context/immutable appended operation-binding file and exact current candidate roster; it never compares successor roster to initialRoster. Native boundary-start schemaVersion2 replaces `originalRosterSha256` with `terminalSha256` and adds context-matching `executionKind`; request/ack/receipt formats and five-second bound stay unchanged. Native boundary-completed schemaVersion2 retains existing keys plus `terminalSha256`, context-matching `executionKind` and `predecessorFinals`; `finals` are exactly terminal pair and all predecessor refs remain independently verified. No v1 field reinterpretation. Future A owns the immutable `native-operation-binding.json` creation; B reads strict bytes/shape/digest only.
