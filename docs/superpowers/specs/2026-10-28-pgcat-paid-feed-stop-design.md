# Barrier-bound paid feed and exact graceful stop

This unit extends the proven no-scale startup barrier/exit ownership to the paid rehearsal and supplies its pre-finalization feed stop. All public paid release guards remain closed. No finalizer, assessment, abort, local credential cleanup promise or live action is enabled here.

## Exact feed launch

Use `LaneClient.start_feed` for both immutable modes, retaining the actual Popen, startup pipe and one-use feed binding before provider execution. Keep no-scale's exact180-second argv and target flag unchanged. Paid uses only the fixed disabled-rehearsal/15-second argv and bound paths, with no no-scale target flag. Validate a canonical integer cap between75 and5400, no more than current Shanghai time remaining to22:30 minus120seconds, and require paid launch before21:30. The controller already derives that cap; the client independently checks it before spawn. A smaller cap may only reduce runtime, never grant permission. Keep `_release_admission` unchanged and enforce it before paid spawn/bind; offline tests patch it only inside tests.

Generalize journal feed binding to these two modes. For paid mode, `Journal.bind_feed(binding, *, manifest_raw=None)` also requires and atomically stores the exact original private outer manifest bytes in a one-use `feed_manifest` record, after checking their SHA against bindingSha256, their lane/capture roots and their inner bindings against the existing private inner binding file. This supplies immutable receipt-path provenance for the later no-argument stop verifier. No-scale calls may omit this new private argument and retain their exact original binding schema; paid may not omit it. Unknown or mismatched manifest data refuses before pipe release. Preserve run/feed IDs, actual live PID, original outer binding SHA and exact verified argv SHA, once only. EOF, timeout or persistence failure must prevent provider execution. `confirm_feed_exit` records only the same retained actual Popen's integer poll result and matching independent binding, including on failure cleanup; no caller PID/status can substitute. Do not require run active merely to record an actual cleanup exit. No source or context mutation can bypass the mode/source checks.

## Paid stop intent and provider acknowledgement

Add distinct fixed sibling files `rehearsal-stop.intent` and `rehearsal-stop.ack`. Intent fields are exactly schemaVersion1, runId, feedSession, minimumSequence, reconcileBindingSha256. The hash is canonical compact ASCII SHA256 of the actual immutable journal reconciliation binding (including sealedAt). No caller assertion substitutes for that binding.

Provider chooses this stop callback only for the actual active disabled-rehearsal journal mode, inventory CLI mode disabled-rehearsal, and no no-scale target flag. A full-replacement inventory mode cannot reuse this paid journal; the full-run observation-only mode remains a separate explicit integration gate. It independently verifies the intent/run/feed/digest, actual journal reconciliation proof, a current successful desired-two exact-original receipt observed after reconciliation sealedAt, and minimumSequence <= actual final sequence <= minimumSequence+1. Stop before the next tick or after an in-progress successful tick; acknowledge the actual final receipt. Natural cap exit alone never produces the acknowledgement or a successful stop proof. Keep15-second interval, retained target history and all source/active-run checks. Target/session drift refuses. No-scale callback/files remain unchanged.

## Actual exit and independent stop proof

`Controller.stop_rehearsal()` requires immutable paid mode, reconciled-two, its exact live retained feed, a matching journal proof, and a newer exact-two receipt observed after reconciliation sealedAt. Write/fsync the intent once, wait on that exact Popen for at most30seconds, require actual code0, then validate actual last receipt and one acknowledgement. At most one further publication is allowed. Final receipt is under30seconds old. Seal the same-handle exit confirmation through the client.

`Journal.record_rehearsal_stop()` takes no caller proof. It reads the fixed private intent/ack and actual receipt path from the independently stored original outer manifest, compares the current inner binding file to that original, checks those paths stay within this capture root, and validates exact canonical records against the original feed binding/exit confirmation, actual reconciliation binding and original-roster digest. Require active paid run and independent zero exit. Persist one immutable `rehearsal_stop` proof with final receipt and its identity, bound feed/exit/reconcile/intent/ack evidence. Getter `rehearsal_stop()` exposes it for later finalization. Repeated record/stop refuses; changed fields, stale receipt, unknown exit or forged caller status cannot create the proof.

Only after that record, controller enters feed-stopped and returns its exact feed-exit receipt. Keep the owner liveness pipe open; no normal `_worker_call`, provider call, new publication wait or journal finished transition is allowed. Post-stop validation/finish is a later dedicated admission path. A first-stop failure remains uncertain and preserves evidence. A duplicate stop or normal worker call after an authenticated successful feed-stopped result must refuse before dispatch while preserving that proof, state and owner pipe; explicit close still disconnects for abort/operator cleanup. never claim killing a local CLI cancels remote execution.
