# Native PgCat observer and rolling client evidence

Status: implementation design for the owner-authorized POC continuation. This document does not establish deployed behavior or a live PASS. Native direct replacement and inventory contracts are reviewed source prerequisites; remaining observer admission and closure are still closed.

## Outcome and authority

Observe one native Raptor-owned 2→4→2 replacement, including one rolling restart of the bound client Deployment, in one continuous retained traffic window. Both originals stop accepting new connections before restart; fresh complete active/idle/waiting observations on both precede the single scale-in. Preserve two exact healthy protected replacements. Native convergence remains `acceptance: pending` until traffic, action/approval evidence and closure are independently complete.

Use `direct-v2` for the harness profile and result version2; use `full-replacement-direct-v2` for Python inventory/observer mode. Preserve legacy v1 originalRoster and staged/disabled-rehearsal interpretation. Never move skills-v0.4.0; a new request uses the reviewed immutable direct release and exact SHA.

Raptor/Infra own every fleet mutation and approval. The observer has no local ESS/NLB/protection templates. Existing fixed ConfigMap target publication/reconciliation, exact client finish and guarded Gateway enable/restore remain separately scoped support operations. No new service, HTTP API, cloud resource, DB provenance store or arbitrary-shell path. Workbench CLI has priority for authorized ACK work. No paid 2→3→2 prerequisite or candidate-Pending bundle is needed for this direct path; actual source, owner, evidence and cleanup gates remain mandatory.

## Disabled proof and full replacement are disjoint

The immutable plan and v2 context require `executionKind`, exactly `native-replacement` or `disabled-proof`. Both use Python inventory mode `full-replacement-direct-v2` and the same client rolling-evidence mechanics. The diagnostic kind exists to exercise an actual bound application restart, terminal successor finish and closure cheaply while Gateway replacement remains false and the exact original two-node fleet stays unchanged. It does not invent a Raptor request, model, result, approval or scale event.

Operation binding `kind` must equal context executionKind. Native bindings carry authenticated Raptor/Gateway request/result/event fields; disabled bindings carry only the actual operator restart receipt hash/generation, plan hash and authenticated ingress hash. Unknown/extra fields and cross-kind binding refuse. Context, terminal witness and finish boundary retain the kind; it cannot change or upgrade on resume.

Future A/C must enforce Gateway false and exact constant desired2/original fleet/healthy protection throughout disabled proof, plus only the fixed UID-bound application restart support action; local fleet templates remain unreachable. Only its separately labelled diagnostic verdict may call ordinary assessment with `require_transition=False`, joined with complete constant-fleet evidence. Full replacement always requires transition and actual native binding. Diagnostic PASS qualifies the observer path only and is never native replacement PASS. Neither B nor a caller-supplied kind grants action authority.

## Capture begins before a request exists

Raptor Create queues and inserts dispatch outbox atomically; no draft/withhold API exists. For native-replacement, start the collector/feed with an immutable capture plan containing executionKind, exact target/application UID, source hashes, planned model/skill/operation, original fleet/client baseline and a fresh run ID. A disabled-proof plan instead binds its fixed operator application-restart action and carries no fictional native request/model/result fields. `planSha256` is not server `definitionSha256`. Retain two committed baseline frames and exact collector-ready identity before guarded enablement and normal signed-in request creation. Other producers remain quiesced during guarded enable/rollout/verify. Append the actual request binding after independently reading it; never rewrite the initial context or baseline.

Future unit A's fixed worker reader uses existing authenticated GETs: Raptor context through OpenAPI service Basic; Gateway request and fully paginated events; existing approval reads. Resolve existing `SERVICE_USERNAME`/`SERVICE_PASSWORD` from exact Gateway Deployment Secret references in worker memory. Fixed private origins/paths, no redirects, bounded response bodies, credentials never sent to Mac/argv/logs. It must validate normalized definition, scope, selected/actual model and immutable skills against the plan. An API association is evidence, not mutation authorization.

Guest ProgressWriter assigns occurredAt before each tool call; Gateway preserves it in `execution/live_journal.go`. Gateway events provide tool names/outcomes/runtimeSequence, not arguments. A successful guarded v2 result contains the exact cohort, two scale actions and actual `restartGeneration`; its ordered two scale starts map to expansion/reduction. Join that result with authenticated event chronology, approvals and retained observations. Do not add result timestamps or a checkpoint archive reader. Provider desired transitions alone do not prove pre-scale zero metrics or exact approval.

## Existing pieces and the one missing client contract

Reuse `pgcat_collector_control` detached capture Popen/guardian, source bootstrap, private-file checks, one-use intents, exact Linux process tuples and finite timeouts. Reuse the Mac supervisor's owned feed Popen/global lock/journal, provider sidecars and immutable frame references in `segmented_capture`. Existing ordinary `capture_window.assess` already handles full startup histories, predecessor final counters, active roster continuity and failure precedence. Current v1 private progress instead pins two original processes and a fixed generation; it must remain unchanged for legacy captures.

Native context v2 permits exactly two initial and two successor process identities for one rolling restart. A successor must be attributable through Pod→ReplicaSet→the same Deployment UID, with the same immutable client image digest. Baseline has one stable initial ReplicaSet/template hash; successors share one new ReplicaSet/template hash. Changed image, foreign owner, second container/process in one Pod, more than four cohort identities, extra rollout, or unexplained disappearance cannot PASS. During rollout, initial generation or initial+1 is observable; once advanced it cannot regress. The later authenticated native result or diagnostic operator restart receipt, selected strictly by executionKind, must report exactly initial+1. Unready or terminating rollout pods are observations, not automatically evidence failure; missing reads, inadequate active traffic, gaps or lost finals remain failures under ordinary assessment.

Capture provisional successor observations before the applicable authenticated restart binding arrives. This permits late binding without dropping early history. Full replacement acceptance requires the actual request/result/event binding; diagnostic qualification requires the actual operator restart receipt binding. Both require the exact one-generation change and complete observed history. Every predecessor needs a settled final before disappearing, every successor needs full event history from1, and every cohort contributes SQL failures. No flags/history are reset when the result is bound.

## Native evidence schemas

Private native progress uses v2, with strict keys, bounded sizes and existing no-symlink/mode0600/0700 rules. The exact callable interfaces are specified in the [first unit plan](../plans/2026-10-29-pgcat-native-rolling-evidence.md).

- Context: common run/feed/provider/source/baseline/collector identity fields plus `schemaVersion:2`, `mode:full-replacement-direct-v2`, immutable `executionKind` and `planSha256`, `initialRoster`, and bound Deployment UID, initial generation/ReplicaSet/template hash/image digest. No requestId is required at capture startup.
- Committed native pod evidence retains existing name/UID/container/process plus allowlisted authoritative ownership `{deploymentUid,replicaSetUid,templateHash,imageDigest,terminating}`. Deployment generation/readiness remains in every frame. Existing SourceFrameRef shape `{basename,device,inode,offset,length,sha256,at}` is reused without relaxation.
- Append-only operation binding references the plan and sealed authenticated ingress digest. Native exact keys are `{schemaVersion,kind,planSha256,requestId,definitionSha256,skillsCommit,model,restartGeneration,resultSha256,eventsSha256,ingressSha256}`. Disabled exact keys are `{schemaVersion,kind,planSha256,restartGeneration,restartReceiptSha256,ingressSha256}`. Both use schemaVersion1 and their matching kind; all restart evidence must agree with capture. The B helper validates consistency only; future A establishes authentication and chronology.
- Terminal witness binds two consecutive actually committed frames (gap≤3s, each age≤3s), an independent current owned Deployment/ReplicaSet/Pod read, same final generation, exactly two ready nonterminating successor processes, both predecessor settled-final frame references and all four cohort first/final references. It includes executionKind, the capture binding hash and operation-binding hash. No caller-selected roster.
- Final boundary targets this terminal pair, using `finish_clients.finish(expected_roster=...)`. All cohort final refs remain retained; the terminal pair is a required subset, not an excuse to delete predecessor finals. Exact request/ack/receipt and durable successor finals must complete within the existing five-second settling boundary.

These witnesses are bounded evidence, not PASS verdicts or runtime capabilities. Source/runtime dispatch remains closed until A and C are reviewed and integrated.

## Bounded implementation units

**B — rolling evidence, first:** add native-only context/ownership/cohort/progress/terminal witness/finish-binding support in stable collector modules, plus offline fixtures. Keep legacy v1 paths unchanged. No controller actions, live profile admission, credentials, API reader, guardian rollout or source-release enablement in this unit. The callable native path is reachable only through explicit v2 context supplied by tests/future reviewed caller; existing CLI/guardian cannot construct it.

**A — native admission and evidence ingress, later:** integrate the explicit observer mode through Journal, fixed ActionCatalog, source bootstrap/collector source registries, supervisor/controller and direct feed. Hard-deny local fleet mutations. Derive plan/ready/request records, fixed authenticated GET ingress, event paging and attempt-spanning chronology for native-replacement; derive real fixed operator restart receipt and constant-fleet/Gateway-false evidence for disabled-proof. Preserve actual Popen ownership, signal/deadline behavior and source verification; do not bypass release admission by calling helpers directly.

**C — stop, verdict and closure, later:** require context-matching operation binding and verdict class; for native-replacement independently verify final replacement pair, reconcile exact ConfigMap UID/resourceVersion/targets after old coverage obligations close, require subsequent same-session publication, stop only the owned feed and bind actual final receipt/exit. While final inventory remains <30s old, invoke native terminal-bound finish. Verify capture child and guardian exit, assess all manifest segments, join approvals/action/zero evidence, seal verdict, settle/disable Gateway, restore finished clients and verify replacement targets plus both temporary credential absences. `finished` means orderly closure, not PASS. For disabled-proof, reconcile the same original fleet and finish the actual successor client pair without synthetic native records; only its constant-fleet diagnostic assessment omits replacement transitions. Do not reuse original-survivor rehearsal close or its candidate proof dependencies.

## Qualification and risks

No source-only claim establishes live success. Keep `replacementEnabled=false` until complete A/B/C review, image/source verification and the cheap disabled-proof application-restart/finish/closure proof. Then one continuous actual native run under existing authorization. Respect the CNY1,800 whole-POC net ceiling, with one billing check per day at preflight; the ceiling does not reset daily. No new paid mutation after21:30 Asia/Shanghai and bounded stop/closure by22:30. Reserve the120s client final hold plus assessment, readback, restoration and cleanup. No extra resource is needed.

Preserve `FAIL > INCONCLUSIVE > PASS`: authenticated SQL failure survives malformed later evidence or cleanup uncertainty; gaps/skips/missing coverage cannot become PASS; clean successors cannot erase predecessor errors. Legacy captures stay readable. Wall-clock comparison alone is not startup authorization: retain actual controller ordering and complete event evidence. Kubernetes ownership/image reads and source-frame bytes must remain bound through terminal selection and finish. Source changes after proof invalidate affected hashes/proof rather than being omitted.
