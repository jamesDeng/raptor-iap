# PgCat action observation time and bounded Gateway reads

Owner approved the measured Gateway timing proposal on Nov3. This records the same approved contracts for implementation. Scope remains three existing production modules within the cumulative15-path union; no new resource, IAM, API, dependency, source-registry key or controller. Replacement remains disabled until the existing real closed disabled proof passes. Preserve old INCONCLUSIVE records.

The actual read-only restart composition exceeded its unchanged five-second action budget. A fresh observation also postdated the entry timestamp incorrectly used to validate it. This change corrects observation decision time and combines duplicated immutable loaded-configuration work while retaining fresh current identity checks.

## Defect and smallest correct change

`pgcat_native_ingress.py:353-410` takes `at=now()` before admission, process reads, capture replay, client reads, provider read, Gateway config/runtime and ConfigMap reads. `_observe` in `pgcat_native_closure.py:244-268` correctly sets runtime observedAt after its own actual I/O. Passing the old action entry time to `_runtime` therefore makes an ordinarily fresh result appear future-dated. The same entry timestamp can incorrectly keep an old frame/provider/sample fresh across slow later reads.

Implement the following in the existing function, preserving data and structural predicates:

1. Retain entry time as `started` only for finite/nondecreasing clock checks. Perform structural identity, ownership, roster, source, progress and comparison checks on the same retained objects as today. Do not reject a newly read frame/provider/runtime merely because it postdates entry.
2. Retain the conditional runtime result, rather than validating its age against entry time. Finish the existing initial ConfigMap read and `chain.unchanged()` before taking final `at=now()`; require finite `at >= started`.
3. Permit at most one bounded end-of-observation progress reread, following the already-reviewed `seal_ready` pattern: retain the initial committed prefix bytes/file identities before live reads; if the tail advances, require nondecreasing generation/attempts/committedFrames/lastCommitMonotonic, unchanged firstAt, no flags or gap violation, replay the new committed prefix independently, and verify the old prefix is unchanged. Recheck the same live roster/ownership against the actual final latest frame. No loop, history replacement, skipped failure or resampling until a favorable result. Take the completion timestamp after this replay/source verification. At that common instant, require latest frame age0..3, pair separation greater than0 and at most3, and provider source age0..<30. When runtime is required, call `_runtime(runtime,plan,at)`. When `initial=True`, call the existing `_ready_pair(previous,latest,baseline,context,at)`, preserving each baseline frame's age and metrics observed/source age0..15, successful advancement and completeness checks, and the mutation cutoff check. Return this completion time in `state['at']`.
4. Recheck the original `gate.admission(action)` at the end and require equality with the original admission. This uses the gate's existing worker deadline; do not compare Mac and worker monotonic values, create a new deadline, or give a new lease. It is another local admission check, not another provider publication or effect. Keep the supervisor and Journal's original five-second outer deadline unchanged.
5. Apply the baseline-pair predicates only where they already apply (`initial=True`). Native ingress after a rollout must not be forced back to the initial roster or initial generation. General actions still get their existing current-frame/provider/runtime checks at completion. The sole bounded healthy-tail advancement above is permitted; a changed original prefix, failed initial evidence, or final stale pair still refuses. This preserves continuous evidence rather than pinning readiness to a tail that legitimately advanced during live reads.

This is more than replacing `_runtime(...,at)` with `_runtime(...,now())`: that two-line fix alone leaves the action returning evidence assessed against an earlier time.

`gateway_false_idle` (`pgcat_native_closure.py:807-814`) has a related **missing final check**, not the same negative-age bug. It performs idle/metadata reads after `runtime_proof` timestamped its result. Revalidate the returned runtime at a new completion time after those trailing reads and adapter checks; require nondecreasing finite time. Preserve its original observedAt and all before/after comparisons. Never fabricate an observation at function return. Its existing3.5s worker budget normally bounds this age; final validation makes the contract explicit and testable.

For `NativeController._abort_gateway_false`, validate the actual returned false-runtime schema/run/plan/age with `_runtime(result,prepared['plan'],time.time())` after `_owned_worker` returns, in both existing branches, before handing it to `abort_owned`. This retains original observedAt across transport and prevents non-None but stale/malformed evidence from earning `verified-disabled`. It does not add any worker call. Abort must still try both credential cleanups independently on failure. The actual run's Gateway unknown has no logged cause; do not label it fixed by this clock change without timing evidence.

## Measured optimization proposal — 2026-11-03 follow-up

This section supersedes the earlier unmeasured timing decision. Independently read `working/handoffs/2026-11-03-restart-read-composition.json` in the parent Infra Ops project. The actual read-only sequence took **8.064776495 seconds**, excluding replay, prepared checks, Workbench/bootstrap/Journal overhead and PATCH. Its three actual runtime inspections cost2.072356,2.166496 and2.141029 seconds. The current composition cannot meet the original5s action limit; another proof with only a clock correction is not justified.

**Recommended combined change:** retain both action gates and the immediate pre-patch guard, but perform the expensive loaded-runtime inspection only once within the original admitted `native-disabled-restart` action, bound privately to its exact WorkerGate and FixedWorkerReads objects. Subsequent checks in that same context require fresh matching identity snapshots, reuse only its private actually-issued runtime observation, and preserve its original observedAt. In addition, fetch the three independent fixed Gateway metadata objects concurrently inside each snapshot. This is bounded reuse of an immutable loaded-configuration fact, not cached current Kubernetes state, a durable proof cache or a new action protocol. Combine it with the completion-time and bounded-prefix correction above before review/calibration/retry.

### Why the loaded-configuration fact can be reused

The code supports the premise under the stated exclusion of a privileged host/runtime adversary:

- `components/agent-gateway/cmd/gateway/main.go:116-118` reads the private config once at process startup; `:153,165,177` copies it into runtime adapters and copies ReplacementEnabled into the live worker. Inspection found no production reload assignment or reload/signal path that changes that flag within the same process.
- `tools/gateway-live-gate/runtime_binding.go:83-157` requires the exact direct Gateway command and config path, pinned image, successfully completed exact init-copy script, private memory volume, Gateway read-only mount, and absence of another init/sidecar/ephemeral container with access to that volume. The guard compares the exec-read copied bytes to the intended Secret and checks the same Pod/config binding again (`main.go:509-629`). The Helm material agrees (`helm-chart/raptor-platform/templates/services.yaml:108-123,239-248,282-286`). These files are inspected evidence only; do not edit them.
- Normal Secret projection changes cannot modify the init-copied private file. A Gateway container restart changes its container runtime identity; a rollout changes Pod/container/spec identity. Secret or Deployment changes also change their API versions. Those changes must invalidate reuse even when the new flag remains false.

This reasoning is conditional on using the actually pinned guard/Gateway bytes already admitted by the runtime-assets manifest; root must retain the binary/image/source binding evidence. A bare Pod UID is insufficient because a container can restart inside the same Pod. The existing `_metadata` projection lacks the required container/process and binding fingerprints, so **reusing its current result alone is rejected**.
