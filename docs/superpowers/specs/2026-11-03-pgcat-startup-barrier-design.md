# PgCat startup ownership and readiness barrier

Owner approved the bounded startup proposal on Nov3, including one additional existing production path: cumulative scope15 rather than14. This is a startup lifecycle correction, not a change to PgCat replacement policy.

Actual disabled startup timed out because Gateway/source checks, process launch, two frames, readiness proof and transport all occupied one five-second external action. Split existing launch acknowledgement from readiness production. The existing guardian retains its actual collector Popen, acknowledges exact ownership through a private inherited channel, then performs one readiness proof under a fixed four-second deadline from collector spawn. Existing collector-status consumes that original authenticated result on a later provider publication. It never reseals readiness or refreshes original readyAt. No new worker process/controller/service.

Launch returns only actual retained guardian/collector tuples, exact intent/result bindings and private authentication material. A LAUNCHED result grants no restart, ingress, Gateway enable or Create authority. The Mac retains identities immediately after acknowledged launch. Status requires one completed exact launch and authenticates the single result against its original binding, prepared anchors and source/process identities. Readiness stays bound to the original fresh Gateway runtime and original readyAt even if status arrives after that runtime would be too old for a new seal.

Use a private inherited pipe for original parent/child ownership and transfer of per-launch authentication key, following the existing worker_control keyed-result pattern. No argv secrets, caller PIDs or arbitrary sidecar adoption. Exclusive bounded result publication binds run, plan, original intent, both tuples, ready bytes/digest/file identity, original readyAt and destination. Missing, failed, changed or unprovable result refuses. Guardian failure stops/waits its actual child. Its existing total capture lifetime is not extended by startup work.

Preserve five-second external actions, four-second proof, three-second frames,15-second metric/source ages,30-second original runtime/provider freshness at the original decision,75–900second capture admission, one publication/one action, SQL failure precedence, complete evidence, approval and cleanup gates. Keep minimum2, desired≥minimum and combined retiring active+idle+waiting≤1. Replacement stays disabled until an actual new closed disabled proof passes.

Production changes only existing pgcat_native_controller.py, pgcat_lane_protocol.py and pgcat_collector_control.py. Tests cover actual owned channel/process behavior, delayed status, original timestamps, all consumers, forgery/PID reuse/changed binding/partial result/crash/deadline/duplicate rejections. No new IAM, resources, public API, dependency or provider cadence. Existing foreign-sidecar abort rejection remains. Lost launch acknowledgement remains honestly unknown with independent exact recovery; no broad cancellation architecture is included. Never alter old failed Journals or fabricate qualification.
